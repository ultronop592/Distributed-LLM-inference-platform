# ADR-002: Outbound WebSocket protocol between gateway and worker agent

## Status
Proposed

## Context
Workers run on a machine that is not publicly reachable (home PC behind NAT) while the gateway runs on a cloud host. The gateway cannot open connections to the worker, so the worker must connect out and keep the connection open. Responses are token streams, so the protocol must support multiple streamed responses at once over one connection.

## Decision
One WebSocket per worker, opened by the worker to `wss://<gateway>/workers/connect`. Messages are JSON text frames with a `type` field.

### Handshake
Worker sends the registration token in the `Authorization: Bearer` header when connecting. The gateway rejects an invalid token with HTTP 401 before upgrading.

### Messages: worker to gateway
| type | Fields | Purpose |
|---|---|---|
| `hello` | `worker_name`, `models` (list), `max_concurrency`, `agent_version` | First message after connecting |
| `heartbeat` | `running`, `waiting`, `kv_cache_usage` | Every 5 seconds, carries load for routing |
| `response_start` | `request_id`, `status` | vLLM replied, with its HTTP status |
| `response_chunk` | `request_id`, `data` | One raw SSE line or JSON body piece |
| `response_end` | `request_id` | Stream finished normally |
| `response_error` | `request_id`, `message` | vLLM failed or timed out |

### Messages: gateway to worker
| type | Fields | Purpose |
|---|---|---|
| `welcome` | `worker_id`, `heartbeat_interval` | Reply to `hello` |
| `request` | `request_id`, `path`, `body` | A chat completion to run |
| `cancel` | `request_id` | The client disconnected, stop generating |

### Rules
- `request_id` is generated by the gateway and ties chunks to the waiting client.
- The gateway marks a worker offline if no heartbeat arrives for 15 seconds, and fails its in-flight requests with 502.
- The worker reconnects with exponential backoff (1 s, doubling, up to 60 s, with jitter).
- A worker that reconnects gets a new `worker_id`.
- The gateway sends a request only to workers that list the requested model and have free concurrency.
- Prompts and completions are never logged by either side.

## Consequences
- No inbound ports on the worker machine.
- If the gateway sleeps (Render free tier), the connection drops and the worker reconnects when it wakes.
- Backpressure is simple: the gateway tracks in-flight requests per worker against `max_concurrency`.
- Custom protocol means writing and testing it ourselves. Alternatives considered: a tunnel (Cloudflare Tunnel or Tailscale) that exposes vLLM directly, which is simpler but gives the gateway no view of worker health or load.
